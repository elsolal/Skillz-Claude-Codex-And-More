# v6.1 migration — unused skill cleanup

This cleanup removes skills and commands that had no recorded use since May 2026, duplicated an
installed plugin, or were superseded by a native runtime feature. The `/dev` → quality-gate →
`/ship` workflow is unchanged.

## Removed artifacts and replacements

| Removed | Use instead |
|---|---|
| `figma-use`, `figma-generate-design`, `figma-implement-design`, `figma-code-connect`, `figma-create-new-file`, `figma-create-design-system-rules` | The official `figma@claude-plugins-official` plugin (`figma:figma-use`, `figma:figma-design-to-code`, `figma:figma-generate-design`, `figma:figma-code-connect`…). `figma-generate-library` and `figma-design-code-sync` stay local. |
| `orchestrate`, `/orchestrate` | Native subagents, or the Claude Code Workflow tool for large fan-outs |
| `code-reviewer` | `quality-gate` (native `/code-review` as correctness lens) or `/code-review` directly |
| `code-implementer`, `github-issue-reader`, `test-runner` | `/dev` (the workflow reads the issue, implements and runs the manifest tests itself) |
| `security-auditor` | Native `/security-review`; `supabase-security` for Supabase projects |
| `output-skill` | Not needed with current models |
| `elevenlabs`, `remotion` | The separately installed `elevenlabs-*` and `remotion-*` skills |
| `multi-mind`, `/multi-mind`, `.env.example` | `/rodin` and `/elicit` |
| `gpt-tasteskill`, `brutalist-skill`, `stitch-skill`, `images-taste-skill` | `taste-router` with `taste-skill`, `soft-skill`, `minimalist-skill` or `redesign-skill` |
| `api-designer`, `database-designer` | `architect` |
| `/init` | Native `/init` |
| `/refactor` | Native `/simplify`, or `/dev` for a scoped change |
| `/docs` | `/dev` (documentation is a regular task) |
| `/metrics` | `/status` and `/retro` |
| `/changelog` | `/ship` (writes the CHANGELOG) |

## Update behavior

`install.sh update all` purges the removed skills and commands from `~/.claude` through the
Skillz manifest (`~/.claude/.skillz-manifest`), and the dead-symlink sweep cleans `~/.codex/skills`.

Not cleaned automatically:

- dead symlinks to the removed skills in `~/.gemini/skills`, `~/.config/opencode/skills` and
  `~/.agents/skills` (only the Codex mirror has a dead-link sweep);
- `knowledge/multi-mind/` in `~/.claude` and in project installs;
- legacy project-level installs (`install.sh` without `--global`): they have no ownership manifest,
  so the removed skills and commands stay in the project's `.claude/` until deleted by hand. The
  manifest-owned `bin/skillz` path removes them on update.

A local `.env.local` created for multi-mind is never touched; remove it yourself if it is no longer
needed.
